Recursive In-Order Traversal Invariant

An in-order traversal strictly visits binary tree nodes in non-decreasing order if and only if the underlying binary search tree property holds. It guarantees left-subtree precedence over the parent locus.

traversal.cpp
C++20 
void inOrderTraversal(TreeNode* root) {
    // Base Case: empty subtree has no elements
    if (root == nullptr) return;

    inOrderTraversal(root->left);   // 1. Recurse left
    visit(root->val);               // 2. Process node
    inOrderTraversal(root->right);  // 3. Recurse right
}
shield Memory Guard: The base check safely terminates recursion before accessing root->left, avoiding fatal segmentation faults on leaf leaves.

Why check root == nullptr before accessing root->left?

If root is null, dereferencing root->left triggers an immediate memory violation (SIGSEGV). Isn't it cleaner to check if (root->left != nullptr) before invoking recursion?

Teaching Staff (Head TA): 1h ago

Great intuition! The single base-case if (root == nullptr) return; guard preserves structural simplicity and elegance. If you guard before every recursive call, you must write duplicate guards for both root->left and root->right, plus handle edge-cases where the initial root itself is null.
